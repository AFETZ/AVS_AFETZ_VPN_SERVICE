# AFZ OpenFlux для Android и iPhone

Отдельный тестовый клиент AFZVPN для транспорта Яндекс Документы, совместимый
с выходным узлом OpenFlux `a8a8937c59fbb275603bd53e150ecaf46e92148e`.
Основная подписка, оплата и существующие серверы бота не меняются.

## Установка

**Android 8+ (arm64 и x86_64):** в `@AFZVPN_bot` открыть OpenFlux → Android,
скачать APK **0.1.1** и установить поверх предыдущей версии. Затем в боте нажать
**«Добавить в AFZ OpenFlux»**: приложение откроется и сохранит профиль.
Если открылась страница перехода, нажать на ней «Открыть AFZ OpenFlux».
В приложении нажать «Подключить» и подтвердить системное разрешение VPN.
Root не нужен; выбирать JSON-файл не требуется.

Если Telegram не открывает приложение: в боте нажать **«Скопировать настройки»**,
в приложении — **«Вставить из буфера»**. В старой версии 0.1.0 настройки можно
вставить в поле ссылки вручную. Импорт JSON остаётся доступен через
«Выбрать файл профиля (JSON)».

**iPhone/iPad, iOS 15+:** здесь находятся исходники приложения и расширения
NetworkExtension. Готовой подписанной IPA в пакете нет. Для сборки нужен Mac
с Xcode; для установки — подпись, разрешающая `packet-tunnel-provider`.
В исходниках 0.1.1 добавлен импорт по той же кнопке из бота и из буфера обмена;
ручной импорт JSON также сохранён. Для этих изменений нужна новая сборка iOS.

Кнопка проверки IP открывает внешний браузер. Через подключённый OpenFlux
ожидается `185.239.141.75`. Для проверки белых списков нужно сначала проверить,
что сайт недоступен напрямую в сети оператора, затем открыть его через OpenFlux.
Работа в обычной сети не подтверждает обход при действующих ограничениях.

Один профиль используется **одним клиентом одновременно**: перед тестом телефона
нужно остановить настольный клиент и другие телефоны. Включение мобильного
OpenFlux заменяет другой активный VPN на устройстве. Его подписка сохраняется;
после остановки OpenFlux привычный VPN можно включить снова.

## Устройство клиента и ограничения

`core/mobile` — общее Go-ядро, упаковываемое в Android AAR и Apple XCFramework.
Оно передаёт IPv4 TCP-пакеты системного VPN-интерфейса через совместимый
WebSocket/LZ4-протокол OpenFlux. Android использует `VpnService`, iOS —
`NEPacketTunnelProvider`. Ни браузерный прокси, ни сторонний tun2socks не нужны.

Адрес интерфейса — `10.10.10.2`, MTU — 1280. Этот адрес соответствует
единственному виртуальному клиенту текущего выходного узла. IPv6 блокируется.
UDP-запросы DNS получают ответ с TC, после чего совместимый системный resolver
повторяет запрос по TCP через туннель. Остальной UDP получает ICMP unreachable,
что позволяет приложениям, поддерживающим TCP, быстрее перейти на него.
Звонки, игры, нестандартные DNS-клиенты и другие приложения, требующие UDP,
могут не работать. Фрагменты IPv4 не поддерживаются.

В Android транспортное приложение исключено из собственной VPN-маршрутизации:
это предотвращает петлю, включая начальное разрешение имён Яндекса. Проверка IP
поэтому запускается во внешнем браузере. В iOS транспорт работает в процессе
Packet Tunnel Provider через нижележащую сеть. Сам интерфейс приложения не
выдаёт успешное соединение с Яндексом за подтверждение обхода белых списков.

Повторные соединения используют задержку 2–15 секунд. Остановка отменяет
HTTP-запрос, закрывает WebSocket и освобождает ожидающее чтение пакета.
Очереди и размер распакованного пакета ограничены. Ссылка на документ не
встроена в APK или исходники; профиль выдаётся только администратору в личном
чате бота. Android backups отключены; ключ подписи APK хранится отдельно от исходников.

Кнопка бота использует HTTPS-страницу `/connection?client=openflux`.
Параметры профиля находятся после `#`, поэтому браузер не отправляет их серверу
страницы. Страница не загружает сторонние скрипты и передаёт профиль приложению
через `afzopenflux://import?version=1&document_url=...`. Android также поддерживает
повторный импорт в уже открытое приложение. Импорт сохраняет профиль, но не включает
VPN автоматически; при работающем туннеле новые настройки применяются после
отключения и повторного подключения.

Дополнительного сквозного шифрования транспортного канала в этой версии нет:
соединение с Яндексом защищено TLS, но сервис-посредник является частью пути.
Для теста следует использовать HTTPS-сайты.

## Сборка Android

Проверяемый набор инструментов: Go 1.26.8, JDK 21, Android SDK Platform 35,
Build Tools 35.0.0, NDK 27.2.12479018. SDK устанавливается официальным
`sdkmanager`, либо из архивов Google с проверкой контрольных сумм.
Версия Go Mobile закреплена в `core/go.mod`.

```bash
cd mobile/openflux/core
go install golang.org/x/mobile/cmd/gomobile golang.org/x/mobile/cmd/gobind
export PATH="$(go env GOPATH)/bin:$PATH"
cd ..
export JAVA_HOME=/path/to/jdk
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"
bash build_android.sh
```

Сценарий собирает обе ABI, Java-оболочку, DEX, выравнивает APK для 16 KiB
и проверяет APK Signature Scheme v2/v3. Gradle не требуется. Готовый файл
появляется в `app/data/openflux/afz-openflux-android.apk` относительно корня проекта;
путь можно переопределить через `AFZ_MOBILE_OUTPUT`.
Для повторной сборки только Java/ресурсов можно использовать `AFZ_SKIP_CORE=1`:
потребуется ранее собранный `android/build/core.aar`. При изменении Go-ядра
нужна полная сборка с NDK без этого флага.

Ключ подписи и пароль создаются один раз в `.local/openflux-mobile-signing`
(переопределение — `AFZ_MOBILE_SIGNING`). Для обновления уже установленного
приложения нужно сохранить **оба файла** и подписывать тем же ключом.
Не включать их в архив исходников и не публиковать.

## Подготовка iPhone на Mac

Установить Xcode с iOS SDK, Go требуемой версии и XcodeGen (не ниже 2.40).
Инструменты Go Mobile установить командами из Android-раздела, затем:

```bash
cd mobile/openflux
bash prepare_ios.sh
open ios/AFZOpenFlux.xcodeproj
```

В Xcode выбрать свою Team для **обоих** targets `AFZOpenFlux` и `Tunnel`.
Оба App ID должны разрешать Network Extensions → Packet Tunnel.
Если bundle ID занят, изменить идентификаторы согласованно: расширение должно
иметь идентификатор основного приложения с суффиксом `.Tunnel`.
Выбрать подключённый iPhone и выполнить Run. Для TestFlight нужен отдельный
Archive с подходящими профилями распространения; автоматическая публикация
этим проектом не выполняется.

`prepare_ios.sh` генерирует framework и Xcode-проект из `ios/project.yml`.
На Linux он сообщает о необходимости macOS. Сгенерированная Objective-C граница
Go проверяется отдельно командой `gobind`; это не заменяет сборку с iOS SDK.

## Проверки

В `core/mobile/packets_test.go` проверяются обработка DNS, контрольная сумма,
отбрасывание фрагментов/чужого адреса, границы распаковки и остановка чтения.

```bash
cd mobile/openflux/core
go test ./mobile
```

`core/cmd/tuncheck` — адаптер для интеграционной проверки на Linux x86_64:
он открывает TUN в отдельном сетевом namespace, а транспорт запускает в исходной
сети. Через эту схему проверены системный DNS, HTTPS и адрес выхода постоянного VPS.
Сам по себе этот тест не подтверждает поведение системных VPN API на реальном телефоне.

Android APK собран и проверен на корректность подписи и выравнивания, но запуск
на телефоне пока не проверен. Попытка проверки в локальном эмуляторе остановилась
на нестабильном запуске самой Android-системы на имеющемся сервере; установка
приложения и подключение VPN в эмуляторе не подтверждены. iOS-проект пока
не компилировался с Apple SDK, подписанная IPA отсутствует.

Парсер ссылок проверяется обычным JDK, без Android SDK:

```bash
mkdir -p android/build/import-test
javac --release 8 -d android/build/import-test \
  android/src/uk/superbebra/afzopenflux/ImportLink.java android/tests/ImportLinkTest.java
java -cp android/build/import-test ImportLinkTest
```

Из корня репозитория `node tests/openflux_import_page.cjs` проверяет формирование
ссылок Android/iOS, буфер обмена и отклонение повреждённых профилей на странице
перехода. Эти проверки не заменяют переход из Telegram на настоящем телефоне.
